第 3 课 · 按键消抖：你的第一个信号处理电路

对应教材：《FPGA Verilog 开发实战指南》第 19 章「按键消抖模块的设计与验证」 · 平台：野火征途 Pro · 预计 120–150 分钟 · 上一篇：第 2 课 · 让 LED 闪起来

本课的胜利（两块）：① 写出按键消抖电路并上板——按一下 KEY1，LED 稳定翻转一次，绝不误触发； ② 把仿真流程从"手敲命令"升级为 Makefile 一键驱动（make sim 出波形、make wave 看波形）， 这是你以后所有实验的基础设施。

一、知识：机械按键的"哆嗦"

你已经知道答案的一半：金属触点闭合瞬间会弹跳，产生 5~10ms 的抖动——电平在 0/1 之间反复横跳， 而不是漂亮的阶跃。固件里的你用 delay(10ms) 再读一次来消抖；FPGA 里没有 CPU 睡觉，但有数时钟：

固件消抖（你的旧知识）

读到按键变化 → 睡 10ms → 再读一次确认。CPU 在"等"，期间什么都不能干（或靠定时器+状态标志）。

FPGA 消抖（本课电路）

只要 key_in 是低电平就一直数时钟；期间电平一变高（抖动）立刻清零重数。 能连续数满 20ms 还没被清零，说明这是真按下。电路在"看"，从不"等"。

算术先行（第 2 课的老活，自己先算再看答案）： 20ms ÷ 20ns = 1,000,000 个周期 → 数 0 ~ 999,999 → 需要 20 位（2²⁰ = 1,048,576 > 100 万）。

官方设计（书第 19 章）的精妙处在输出形式：它不输出"电平"，而输出一个 只维持一个时钟周期（20ns）的脉冲 key_flag—— 每次确认按下时闪一拍。为什么这么设计？因为"事件"（按下这件事发生了）和"电平"（现在还按着）是两种信息， 下游电路用寄存器捕获这个脉冲，想要"按一下翻转一次"、"长按连发"都从这一个干净的脉冲出发。

老师提示：20ns 的脉冲人眼永远看不见，所以上板验证时必须用寄存器"接住"它。 本课顶层输出两个信息：key_flag（引到 LED 不可见，但仿真可见）和 led_out（每捕获一个 flag 翻转一次）。

二、实战 A：设计电路

练习场：test/case/03-key-filter/（结构同前：src/ + sim/ + sp1_prj/）。

  1. 先画波形再写代码（野火方法论第 2 步）：在纸上画 key_in 抖动按下 → cnt 反复清零 → 稳定后数满 → key_flag 一拍 → led 翻转。画不出来就翻书 19 章的波形图对照。
  2. 写 src/key_filter.v（先回忆再对照官方 10_key_filter/rtl/key_filter.v）。 在官方基础上加一个输出：output reg led_out，每当 key_flag 有效翻转一次。 记住第 2 课的教训：flag 只有一拍，led_out 必须是时序逻辑寄存器，绝不能 assign led_out = key_flag;。
  3. 新建 Quartus 工程 + 约束：顶层 key_filter，器件 EP4CE10F17C8。 引脚：sys_clk → PIN_E1、sys_rst_n → PIN_M15、key_in → PIN_M2（KEY1）、 led_out → PIN_L7。全编译。
  4. 上板验证：按一下 KEY1 → LED 翻转一次；松开 → 不变；按住不放 → 也只翻一次（想想为什么，思考题 1）。 快速连按，LED 次数跟手——这就是消抖成功的手感。

三、实战 B：仿真（ tb 要自己"制造"抖动）

第 2 课的 tb 只产生了规整的时钟和复位；本课 tb 的新课题是模拟一个机械按键的抖动波形。 思路：用 SystemVerilog 的 task 封装"抖动着按下/松开"的动作（你写过的 C 函数思维，直接迁移）：

task automatic press_key();
    int i;
    // 抖动期：电平随机横跳 8 次，间隔 0~200ns
    for (i = 0; i < 8; i++) begin
        key_in = $urandom_range(0, 1);
        #(20 + $urandom_range(0, 180));
    end
    key_in = 1'b0;                 // 稳定按下
    #(T_STABLE);                   // 稳定时间 > 消抖时长，必出 flag
    key_in = 1'b1;                 // 释放
endtask

两个关键决策，写 tb 前先想清楚：

  • 时间压缩：真实 20ms 仿真太久。例化时 #(.CNT_MAX(20'd99))（100 个周期 = 2µs 消抖时长）， tb 里的稳定时间给 3us（> 消抖时长）。物理 RTL 一行不改。
  • 验证什么：每次 press_key 后恰好出现一拍 key_flag（不是两拍、不是零拍）； 抖动期绝不出现 flag。用 $display 打印 flag 出现的时刻，自己核对。

四、实战 C：Makefile —— 仿真流程工程化

你天天写 Makefile，这块让你自己来。需求清单（先自己写，卡住看答案）：

  1. Makefile 放在 sim/ 目录，工作目录（work/ 库、VCD）也生成在 sim/ 下——别再埋进 sp1_prj 深处。
  2. 目标 sim（默认目标）：vlib 建库 → vlog 编译 ../src/key_filter.v 和 tb → vsim 控制台运行并导出 VCD。
  3. 目标 wave：用 gtkwave 打开 VCD。
  4. 目标 clean：删掉 work 库、VCD、transcript。
  5. 工具路径（/tool/altera/13.0sp1/modelsim_ase/bin）、顶层模块名、VCD 文件名全部用**变量**定义—— 换个实验只改变量，Makefile 结构不动。这是你以后每课复用的模板。
  6. 三个目标都是伪目标（.PHONY），sim 里每步命令失败要能停住（想想 make 的每行错误传播规则，或者用 set -e 思维）。

参考答案（先自己写完再展开）

MSBIN := /tool/altera/13.0sp1/modelsim_ase/bin
VLIB  := $(MSBIN)/vlib
VLOG  := $(MSBIN)/vlog
VSIM  := $(MSBIN)/vsim

TOP   := tb_key_filter
VCD   := key_filter.vcd
RTL   := ../src/key_filter.v
TB    := ./tb_key_filter.sv

.PHONY: sim wave clean

sim: $(VCD)
	@echo "== 仿真完成，波形: $(CURDIR)/$(VCD)  (make wave 查看)"

$(VCD): $(RTL) $(TB)
	$(VLIB) work
	$(VLOG) -quiet $(RTL) $(TB)
	$(VSIM) -c $(TOP) -do "vcd file $(VCD); vcd add -r sim:/$(TOP)/*; run -all; quit -f"

wave: $(VCD)
	gtkwave $(VCD)

clean:
	rm -rf work $(VCD) transcript vsim.wlf

老师提示：注意参考答案把 VCD 声明为目标文件依赖 RTL/TB 源码—— 源码没改时 make sim 不会重跑仿真（增量构建），这是 Makefile 送你的免费福利。 顺带一个坑：vlib work 对已存在的库会报错，参考答案依赖 make clean 或容忍该错误—— 想做得更干净，可以在 shell 命令里先判断目录是否存在。

五、检索练习（合上资料答）

1. 消抖计数器"电平一变高就清零重数"，为什么这样就能消掉抖动？

清零不能"滤除"毛刺（key_in 毛刺仍然一直存在），它的作用是让"数满"这个事件只在电平真正稳定 20ms 后发生一次——用时间换可信度，与固件里 delay 后再读一次是同一个思想。

2. key_flag 只有一拍宽（20ns），为什么不能 assign led_out = key_flag 让 LED 闪烁指示？

assign 只是复制信号，20ns 的脉冲 LED 每秒闪五千万次 = 恒亮/不可分辨。正确做法是让时钟沿捕获事件：flag 有效时翻转寄存器——"事件计数"必须靠时序逻辑。

3. tb 里模拟真实按键抖动，下列哪个说法是对的？

消抖电路的全部价值就在"抖动期间不出 flag"——不给抖动等于没测它。改时钟频率仿出来的不是你的电路；改 parameter 压缩时间才是不动 RTL 的正规做法。

六、通关后的思考题（下一课开场）
