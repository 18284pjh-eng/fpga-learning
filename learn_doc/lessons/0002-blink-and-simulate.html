一、知识：时钟是 FPGA 的心跳

征途 Pro 板上有一颗 50MHz 晶振，它给 FPGA 一个每秒 5 千万次的方波信号 sys_clk，每个周期 20ns。 第 1 课的组合逻辑没有时钟，输入变输出立刻变；而"等 0.5 秒"这件事，在硬件里的做法是：

做一个计数器（一堆触发器），每个时钟上升沿加 1。数到 25,000,000 个上升沿，就是 0.5 秒到了，把 LED 翻转一下，计数器清零。

这就是时序逻辑：输出不只取决于当前输入，还取决于"数到了第几个时钟沿"（状态）。描述它的 Verilog 惯用形式：

always@(posedge sys_clk or negedge sys_rst_n)
    if(sys_rst_n == 1'b0)      // 复位：低电平有效，异步清零
        cnt <= 25'b0;
    else    if(cnt == CNT_MAX)
        cnt <= 25'b0;          // 数满清零
    else
        cnt <= cnt + 1'b1;     // 每个时钟上升沿 +1

三个新面孔，各记住一句话：

新面孔一句话解释
posedge sys_clk时钟上升沿触发。这段电路是一组触发器（寄存器），不是指令循环
<= 非阻塞赋值时序逻辑专用，"大家同时一起更新"。细节第 16 章讲，先照抄养成习惯
negedge sys_rst_n异步复位：复位键（PIN_M15，按下为低）一按，寄存器立刻清零，不等时钟

算位宽（固件工程师的老活）：0.5s ÷ 20ns = 25,000,000 个周期，需要数 0 ~ 24,999,999。 2²⁴ ≈ 1677万 < 2500万 ≤ 2²⁵ ≈ 3355万，所以计数器要 25 位：reg [24:0] cnt;。 数到 24,999,999 就翻转（注意不是 25,000,000——0 也是被数的一个数，想想为什么，测验里有它）。

老师提示：官方例程（征途Pro/08_counter/rtl/counter.v）给了两种写法：直接翻转 LED（方法1）和 先产生一个时钟周期的"数满标志"信号再用它翻转（方法2）。方法2 是更规范的设计习惯—— 标志信号可以被多个逻辑复用。建议你按方法2 写，书上 17 章也是这么推导的。

二、实战六步

新练习场：test/case/02-led-blink/（自己建，目录结构仿照 01-led：src/ + sim/ + sp1_prj/）。

  1. 新建 Quartus 工程：File → New Project Wizard，目录选 02-led-blink/sp1_prj/， 工程名和顶层实体都叫 led_blink，器件 EP4CE10F17C8。一路 Next，最后 Finish。
  2. 先回忆，再写 src/led_blink.v：模块带一个 parameter CNT_MAX = 25'd24_999_999 （为什么用 parameter？仿真时要改小它，见第 6 步），端口 sys_clk / sys_rst_n / led_out。 写完对照官方 08_counter/rtl/counter.v（模块名改成你的即可）。
  3. 加入工程 + 分配引脚：Files 标签右键 Add/Remove Files；Pin Planner： sys_clk → PIN_E1、sys_rst_n → PIN_M15、led_out → PIN_L7。 顶层不是 led 了，确认 Top-Level Entity 是 led_blink。
  4. 全编译（Ctrl+L）。编译后去 Flow Summary 看：Total registers 应该是 26（25 位计数器 + 1 位 LED 翻转寄存器）—— 这就是你刚"画"出来的触发器数量。
  5. 下载上板：Programmer（这次 Hardware 里应该能看到 USB-Blaster 了）→ Start。 现象：LED 每半秒翻转一次 = 1Hz 闪烁。试着改 CNT_MAX 为 25'd124_999_999 重编译， 观察闪烁变慢（5 秒一个来回）——体会"计数器值 = 时间"。
  6. 仿真验证（重点新技能）：真实电路 0.5 秒才闪一下，仿真等不起——把 CNT_MAX 改小就行， 这正是 parameter 的好处。写 sim/tb_led_blink.v： 
    `timescale 1ns/1ns
module tb_led_blink();

reg  sys_clk, sys_rst_n;
wire led_out;

// 把 0.5s 压缩成 250 个周期（5us），现象相同、仿真飞快
led_blink #(.CNT_MAX(25'd249)) u_led_blink(
    .sys_clk  (sys_clk  ),
    .sys_rst_n(sys_rst_n),
    .led_out  (led_out  )
);

initial sys_clk = 1'b1;
always #10 sys_clk = ~sys_clk;   // 50MHz：半周期 10ns

initial begin
    sys_rst_n = 1'b0;
    #30
    sys_rst_n = 1'b1;            // 30ns 后释放复位
    #20000
    $stop;                       // 仿真 20us，足够看到多次翻转
end

endmodule
    用 Quartus 自带的 ModelSim-Altera 仿真（书第 9/17 章有截图级步骤，或翻《ModelSim电子系统分析及仿真》）： Assignments → Settings → EDA Tool Settings → Simulation，选 ModelSim-Altera、Format 为 Verilog， 在 Compile test bench 里指定这个 tb 文件。运行后在波形窗里量一量：led_out 每隔 5000ns 翻转一次，和手算一致。

三、检索练习（合上资料答）

1. 计数器要数 0.5 秒，为什么数到 24_999_999 就翻转，而不是 25_000_000？

0~24,999,999 恰好 25,000,000 个值。这种"差一"错误是计数器设计的经典坑——数满标志在 cnt == CNT_MAX 时拉起，如果 CNT_MAX 写成 25_000_000，25 位寄存器根本数不到，LED 永远不闪。

2. always@(posedge sys_clk) 里的语句，综合出来的电路是什么？

这正是时序逻辑和组合逻辑的分水岭：寄存器只在时钟沿采样输入，其它时间保持原值。"clk 为高期间持续执行"是 C 思维的陷阱——硬件里没有"执行"，只有"采样与保持"。

3. 想在仿真里 20 微秒就看到闪烁效果，正确的做法是什么？

parameter 是把模块做成"可配置电路"的关键：仿真用小值看行为，上板用真值看现象，RTL 源码一行不用改。改 timescale 只改打印单位、不改仿真耗时；改时钟频率则仿真出来的已经不是你的真实电路了。
