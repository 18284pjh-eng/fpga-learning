第 5 课 · 流水灯：时钟使能、状态序列与多路输出

对应教材：《FPGA Verilog 开发实战指南》第 10～13 章 · 平台：野火征途 Pro · 预计 120–180 分钟 · 上一篇：第 4 课 · 状态机 FSM

本课的胜利：让 4 个板载 LED 按固定顺序移动，并用仿真证明每一步只在指定的时钟使能到来时发生。 你会把“计时”和“状态序列”拆成两个清楚的电路，再用 Makefile 完成仿真、综合和下载。

〇、开场复习

  1. 第 4 课的状态寄存器为什么使用非阻塞赋值？状态在一个时钟沿改变几次？
  2. 50MHz 时钟下，0.5 秒对应多少个时钟周期？计数器的最大值应写成周期数还是周期数减一？
  3. 第 4 课的 LED 是低电平点亮。若内部信号表示“亮为 1”，送到引脚前需要做什么？

本课的核心：没有 CPU 的 FPGA 不会执行“等待 0.5 秒”这条指令。 计数器每拍前进，数满时产生一个单拍的 step_tick；状态寄存器只在这个使能到来时移动一次。 逻辑仍然运行在同一个 clk 时钟域中。

二、把“慢动作”拆成两个电路

不要把 50MHz 的 clk 直接分频成一个新的时钟去驱动状态机。本课只生成一个时钟使能脉冲：

clk:        _|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_
step_tick:  ____________________|‾|____
state:      LED1 ----------------> LED2

计数器的职责只有一件事：数到阈值时让 step_tick 有效一拍，并从零重新计数。 状态寄存器的职责也只有一件事：看到 step_tick 后从当前 LED 位置进入下一个位置。

2.1 周期计算

50MHz 的时钟周期是 20ns。若希望每 0.5 秒移动一次：

0.5 s / 20 ns = 25,000,000 个时钟周期
计数范围：0 到 24,999,999
需要位数：ceil(log2(25,000,000)) = 25 位

因此 RTL 默认参数可以写成 STEP_CNT_MAX = 25'd24_999_999。 仿真时用参数覆盖把它改成 3 或 4，不能为了加快仿真而修改 RTL 的默认物理时间。

2.2 状态表

用 2 位保存当前 LED 位置。状态编码只是内部约定，输出由组合逻辑译码：

状态名编码led_on（亮为 1）下一个状态
LED12'd04'b0001收到 step_tick 后到 LED2
LED22'd14'b0010收到 step_tick 后到 LED3
LED32'd24'b0100收到 step_tick 后到 LED4
LED42'd34'b1000收到 step_tick 后回到 LED1

注意两个表示：led_on=4'b0001 表示 LED1 亮；由于引脚低有效，外部端口 led=~led_on=4'b1110。如果波形中看到的是 1110 → 1101 → 1011 → 0111，这是正常的外部引脚电平。

三、实战 A：自己写 RTL

练习目录定为 test/case/05-water-led/，沿用前几课的结构：

  1. 先写端口和参数。模块名必须是 water_led；端口是 clk、rst_n、led[3:0]；增加一个可覆盖的 STEP_CNT_MAX 参数。
  2. 完成步进计数器。复位时清零；计数到 STEP_CNT_MAX 时清零。step_tick 用计数器比较得到，在阈值所在的一个周期内为 1。
  3. 完成位置寄存器。复位后状态为 LED1；只有 step_tick 为 1 时才改变状态；LED4 后必须回到 LED1。
  4. 完成组合译码。用 case 把状态映射为 led_on，写出 default 恢复路径，再用位取反得到低有效端口 led。
  5. 自己检查边界。计数器使用“周期数减一”的阈值；状态改变和 step_tick 出现在哪一个时钟沿，要在波形中对齐确认。

建议的代码骨架如下。它故意没有填入状态转移和计数条件，请你自己完成：

`timescale 1ns/1ps

module water_led #(
    parameter integer STEP_CNT_MAX = 25'd24_999_999
) (
    input  wire       clk,
    input  wire       rst_n,
    output wire [3:0] led
);
    localparam [1:0] LED1 = 2'd0;
    localparam [1:0] LED2 = 2'd1;
    localparam [1:0] LED3 = 2'd2;
    localparam [1:0] LED4 = 2'd3;

    reg [24:0] step_cnt;
    wire       step_tick;
    reg [1:0]  state;
    reg [1:0]  next_state;
    reg [3:0]  led_on;

    assign step_tick = (step_cnt == STEP_CNT_MAX);

    // 1. 时序：step_cnt
    // 2. 时序：state
    // 3. 组合：step_tick 与 next_state
    // 4. 组合：led_on，最后 assign led = ~led_on;
endmodule

四、实战 B：先用小参数证明行为

仿真例化时把 STEP_CNT_MAX 改成一个很小的数，例如 3。这里的 3 表示计数范围 0、1、2、3，所以每 4 个时钟周期产生一次 step_tick。testbench 至少要覆盖：

六、进阶：用正弦 PWM 做亮度丝滑流水灯

基础流水灯只有“亮/灭”两种状态。本节把正弦值映射为 PWM 占空比，让每个 LED 的亮度缓慢变亮、变暗， 四个 LED 使用相差 90° 的相位，于是亮度波峰会从 LED1 平滑地移动到 LED4。

高速 PWM：   负责一帧内的亮度比例
慢速 phase： 负责亮度包络的变化
正弦查表：   把 phase 变成 duty（0..255）

LED1:  sin(phase +   0)
LED2:  sin(phase +  64)
LED3:  sin(phase + 128)
LED4:  sin(phase + 192)

6.1 PWM 如何控制亮度

用一个 8 位自由运行计数器产生 PWM 载波：

pwm_cnt: 0, 1, 2, ... 254, 255, 0, ...
led_on = (pwm_cnt < duty)

当 duty=64 时，LED 在每个 PWM 周期内约四分之一时间点亮； 当 duty=192 时，约四分之三时间点亮。50MHz 时钟配合 8 位计数器的 PWM 频率约为 50MHz / 256 = 195.3kHz，肉眼不会看到闪烁。外部引脚低有效，因此最后仍然需要：

assign led[0] = ~led_on0;
assign led[1] = ~led_on1;
assign led[2] = ~led_on2;
assign led[3] = ~led_on3;

6.2 正弦值必须使用查表

testbench 可以调用数学库生成参考波形，但可综合 RTL 不应直接调用带实数的 sin()。 本课使用 ROM/LUT：离线把正弦曲线采样成无符号整数，RTL 根据 phase 读取表项。

  • 亮度范围：用 0..255 表示占空比，0 是全灭，255 接近全亮。
  • 采样数量：先用 16 或 32 个点验证功能，再增加到 256 个点降低阶梯感。
  • 实现方式：Quartus 13 可用 case (phase) 写小表，或用初始化文件推断 ROM；不要在硬件中使用浮点变量。

如果先用 16 点查表，可以把 phase 的高 4 位作为索引；四个 LED 的相位偏移分别是 0、4、8、12。完成基本版本后再扩展到 256 点。

6.3 时序结构

建议保留三个独立职责：

电路更新频率职责
pwm_cnt每个 clk生成 PWM 载波
phase_cnt例如每 10ms让亮度包络缓慢移动
phasephase_tick 到来时读取正弦表的当前位置

50MHz 下，若希望相位每 10ms 移动一次，phase_cnt 的阈值是 500_000 - 1。仿真时把它覆盖成 3 或 4。LED 的亮度波形周期约为 256 × 10ms = 2.56s。

RTL 骨架可以写成下面这样，正弦表函数和复位分支由你补齐：

parameter integer PHASE_TICK_MAX = 500_000 - 1;
reg [7:0]  pwm_cnt;
reg [7:0]  phase;
reg [31:0] phase_cnt;
wire [7:0] duty0, duty1, duty2, duty3;

assign duty0 = sine_lut(phase);
assign duty1 = sine_lut(phase + 8'd64);
assign duty2 = sine_lut(phase + 8'd128);
assign duty3 = sine_lut(phase + 8'd192);

assign led[0] = ~(pwm_cnt < duty0);
assign led[1] = ~(pwm_cnt < duty1);
assign led[2] = ~(pwm_cnt < duty2);
assign led[3] = ~(pwm_cnt < duty3);

always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        pwm_cnt  <= 8'd0;
        phase_cnt <= 32'd0;
        phase    <= 8'd0;
    end else begin
        pwm_cnt <= pwm_cnt + 1'b1;
        // phase_cnt 到 PHASE_TICK_MAX 时清零，并让 phase 加一
    end
end

6.4 把 LUT 放进单独的 .v 文件

函数只能在模块内部使用，不能把一个只含函数的文件直接“调用”。将函数放入模块后，主模块通过模块实例连接它的输入和输出。 本工程的 src/sine_quarter_lut.v 定义了模块 sine_lut：

module sine_lut (
    input  wire [7:0] phase,
    output wire [7:0] duty
);
    // sine_quarter_lut、sine_value 两个 function 放在这里
    assign duty = sine_value(phase);
endmodule

所以 sine_quarter_lut 是模块内部的“四分之一周期函数”，sine_value 是完整相位到 duty 的转换函数， duty 才是模块对外输出的亮度数值。water_led.v 里这样实例化：

wire [7:0] duty0;

sine_lut sine_lut_0 (
    .phase(phase),
    .duty(duty0)
);

实例化语法是“模块名 + 实例名 + 端口连接”。一个模块可以实例化多次；本工程实例化四次，分别给 phase 加上 0、64、128、192 的相位偏移。文件名不要求和模块名一致，但 Makefile 和 QSF 必须把这个源文件列入工程：

# Makefile
$(MSBIN)/vlog -quiet ../src/sine_quarter_lut.v ../src/water_led.v tb_water_led.sv

# water_led.qsf
set_global_assignment -name VERILOG_FILE ../src/sine_quarter_lut.v

ModelSim 的 vlog 需要看到两个源文件，Quartus 的 QSF 也需要登记两个源文件；否则主模块会报 Unknown module: sine_lut 或找不到模块定义。

6.5 仿真应该检查什么

PWM 输出不能只在一个时刻采样，因为一个亮度周期内它会快速翻转。testbench 应在一个完整 PWM 帧内统计 ~led[i] 为 1 的时钟数，再和当前 duty_i 比较：

检查预期
PWM 载波pwm_cnt 连续循环，周期为 256 个时钟
占空比亮的时钟数随 duty_i 增加而增加
相位关系四个 duty 值相差约四分之一周期
亮度包络phase 缓慢循环，duty 先增大后减小

仿真时可以先把 PHASE_TICK_MAX 覆盖为 3，让亮度包络很快变化； PWM 仍保持 8 位，这样正弦表的 0..255 占空比范围不需要改变。若同时降低 PWM 位宽， 必须把查表输出范围同步改成 0..(2^PWM_BITS-1)。上板时恢复实际的相位分频值。

6.6 进阶验收

  1. 四个 LED 的外部电平仍然经过低有效取反，但亮的时间比例随 duty 平滑变化。
  2. 在同一 PWM 帧内 duty 保持稳定，只有慢速 phase_tick 到来时才变化。
  3. 四个 LED 的亮度峰值按 LED1、LED2、LED3、LED4 的顺序移动，没有突然跳亮或全灭。
  4. 使用小参数仿真通过后，再把 PWM 和相位计数器恢复为 50MHz 的实际值上板。

七、常见错误与排查顺序

  1. LED 全灭或全亮：先看是否忘了低有效取反，再确认 QSF 的位序和物理 LED 编号。
  2. LED 亮度不变：检查是否把 duty 直接接成常数，或 phase 计数器是否没有产生慢速更新。
  3. LED 移动太快：检查仿真参数是否只写在 testbench 例化处；上板默认值应仍然对应设计的 PWM 和相位周期。
  4. 每次移动跳过一个 LED：检查状态寄存器是否在没有 step_tick 时也更新，或是否把组合信号误当成时钟。
  5. 波形出现 X：检查复位是否覆盖了计数器、脉冲、状态和输出的初值。
  6. Quartus 找不到端口：逐字核对 led[0] 这种总线索引，QSF 中不能写成不存在的单独端口名。

八、检索练习

1. 为什么本课生成 step_tick，而不是把计数器输出直接当新时钟？

使能脉冲让状态寄存器仍由原来的 clk 驱动，设计更容易约束、分析和复用。

2. 低有效 LED 中，内部 led_on=4'b0001 时，外部端口应是什么值？

内部使用亮为 1 的逻辑表示，连接到低有效引脚时逐位取反，所以 LED1 亮时外部值为 1110。

3. STEP_CNT_MAX=3 时，计数器从 0 开始多久产生一次步进？

计数序列是 0、1、2、3，数到最大值后清零并产生单拍使能，因此周期数是 STEP_CNT_MAX+1。

九、通关标准

  1. 仿真输出连续通过，外部 LED 电平按 1110 → 1101 → 1011 → 0111 → 1110 循环。
  2. 波形能指出 step_tick、计数器、状态和 led 之间的因果关系。
  3. Quartus Map、Fit、Assembler 和单独的 Timing 都能从命令行完成。
  4. 上板后 LED1、LED2、LED3、LED4 依次点亮，移动周期约为 0.5 秒。
  5. 能解释为什么“计数器是时间基准，状态寄存器是位置记忆，组合逻辑是输出译码”。
  6. 进阶完成后，能解释 pwm_cnt 控制载波、phase 控制亮度包络，以及低有效输出为什么要取反。
