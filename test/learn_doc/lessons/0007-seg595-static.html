第 7 课 · 六位数码管静态显示：74HC595 串行移位

对应教材：《FPGA Verilog 开发实战指南》第 25 章「数码管的静态显示」 · 平台：野火征途 Pro · 预计 120–180 分钟 · 上一篇：第 6 课 · 无源蜂鸣器

本课的胜利：用 FPGA 产生 74HC595 所需的串行数据、移位时钟和锁存时钟， 在六位数码管上稳定显示一组数字。你会把一个并行的 14 位显示数据包，按位发送给串行芯片。

〇、开场复习

  1. 第 6 课中，音调计数器和音符时长计数器为什么不能合并？
  2. 为什么 50MHz 时钟不能直接接到数码管的串行移位时钟？
  3. 如果一个寄存器在时钟沿更新，另一个输出组合逻辑读取它，读取到的是更新前还是更新后的值？

本课的关键：74HC595 先把数据逐位移入内部移位寄存器， 再用锁存时钟把完整数据一次性送到输出寄存器。移位过程中，外部数码管不会看到半包数据。

一、确认硬件接口

征途 Pro 使用 74HC595 扩展数码管输出。FPGA 只需要控制四条信号：

端口引脚作用
clkPIN_E150MHz 板载时钟
rst_nPIN_M15低有效复位
dsPIN_R1串行数据输入
shcpPIN_B1移位时钟
stcpPIN_K9锁存时钟
oePIN_L11输出使能，低有效

本课先显示固定的 012345 或 123456，暂时不加入按键和动态数据。 先把 74HC595 的时序独立验证清楚，后面再把蜂鸣器的状态或计数值接到显示模块。

二、14 位数据包是什么

六位数码管需要两类并行信息：

字段位宽含义
sel6 位六个数码管的位选
seg8 位a、b、c、d、e、f、g、dp 段选

合计 6+8=14 位。官方控制器把它们拼成一个移位数据包：

data = {seg[0], seg[1], seg[2], seg[3],
        seg[4], seg[5], seg[6], seg[7],
        sel[5], sel[4], sel[3], sel[2], sel[1], sel[0]};

这个拼接顺序必须和硬件连线、ds 取位顺序一起验证。不要只根据变量名猜位序， 要在仿真中观察每次 shcp 上升沿前后的 ds，确认发送的是预期序列。

三、三个时序信号的关系

发送一个 14 位数据包时，基本时序如下：

  1. 在 shcp 上升沿到来前，把当前数据位放到 ds。
  2. 产生一次 shcp 上升沿，74HC595 采样并移入这一位。
  3. 重复 14 次，直到整包数据进入移位寄存器。
  4. 发送完成后给 stcp 一个脉冲，把移位寄存器内容锁存到输出寄存器。
  5. oe=0 时允许输出；复位或需要避免半包显示时，可以暂时关闭输出。

因此 shcp 和 stcp 不是同一个信号：

信号作用频率/时机
shcp每一位数据移入一次每包 14 个脉冲
stcp整包数据更新到输出每包 1 个脉冲
oe控制输出是否可见低有效电平

四、推荐的 RTL 分层

本课建议把设计拆成三个模块，顶层只负责连接：

07-seg595-static/
├── src/seg595_static.v   # 顶层：连接显示译码和 595 控制器
├── src/seg_display.v     # 数字到段码、位选数据
├── src/hc595_ctrl.v      # 14 位串行发送和锁存
├── sim/tb_seg595_static.sv
├── sp1_prj/seg595_static.qpf
├── sp1_prj/seg595_static.qsf
├── sp1_prj/seg595_static.sdc
└── Makefile

seg_display 只负责“显示什么”，hc595_ctrl 只负责“怎么发送”。 这种划分让段码错误和移位时序错误可以分别定位。

4.1 先完成移位控制器

可以先使用很小的分频参数进行仿真。控制器至少需要：

reg [1:0]  clk_div;
reg [3:0]  bit_cnt;       // 0..13
reg [13:0] shift_data;
reg        busy;

// 验收重点：
// 1. 一次发送恰好 14 个 shcp 脉冲
// 2. 每个 shcp 上升沿前 ds 已经稳定
// 3. 第 14 位发送完成后只产生一个 stcp 脉冲
// 4. 非发送期间输出保持确定状态

第一版可以让控制器持续重复发送同一个数据包。等重复发送时序正确后，再增加“数据变化才发送”或更新请求握手。

4.2 段码译码

常见共阳数码管段码是低有效。例如数字 0 点亮 a、b、c、d、e、f，关闭 g：

case (digit)
    4'd0: seg = 8'b1100_0000;
    4'd1: seg = 8'b1111_1001;
    4'd2: seg = 8'b1010_0100;
    4'd3: seg = 8'b1011_0000;
    default: seg = 8'b1111_1111;
endcase

具体极性以本板实测和官方例程为准。1111_1111 通常表示全灭， 但位选 sel 的有效电平也必须一起确认。

五、命令行工程与仿真

本课继续使用 Makefile：

make syntax      # 只编译 RTL 和 testbench
make elab        # 检查顶层模块连接
make sim         # 运行自动检查
make wave        # 查看 ds、shcp、stcp、oe、bit_cnt
make map         # Quartus Analysis & Synthesis
make fit         # Fitter
make sof         # 生成 SOF
make program     # 下载已有 SOF

testbench 不需要“看见数字”，而是检查数字显示背后的协议：

  1. 复位后 oe、ds、shcp、stcp 处于确定状态。
  2. 每一帧出现恰好 14 个 shcp 上升沿。
  3. 每个 shcp 上升沿采样到的 ds 位序与预期数据包一致。
  4. 第 14 个移位时钟后出现一个 stcp 脉冲。
  5. 连续观察两帧，确认帧间没有少位、多位或锁存脉冲重复。

六、常见错误

  1. 数码管显示乱码：段码极性、位序或 data 拼接顺序错误。
  2. 只有最后一位数据正确：误把串行移位寄存器当成并行输出，或没有产生 stcp 锁存脉冲。
  3. 显示闪烁或半包更新：在移位过程中没有正确使用 oe，或锁存时机提前。
  4. 仿真计数不稳定：testbench 在错误的边沿采样 ds，应明确发送器和采样器的边沿关系。
  5. Quartus 找不到模块：Makefile 或 QSF 漏列了 seg_display.v、hc595_ctrl.v。

七、通关标准

  1. RTL 和 testbench 通过 make syntax 与 make elab。
  2. 仿真验证每帧 14 个移位脉冲、正确的 ds 位序和一个锁存脉冲。
  3. Quartus Analysis & Synthesis 通过，QSF 包含时钟、复位和 74HC595 的六个正确引脚。
  4. 上板后六位数码管能稳定显示固定数字。
  5. 能说明 shcp、stcp、oe 的职责区别。
