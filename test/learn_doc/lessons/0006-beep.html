第 6 课 · 无源蜂鸣器：频率分频与简单旋律

对应教材：《FPGA Verilog 开发实战指南》第 24 章「无源蜂鸣器驱动实验」 · 平台：野火征途 Pro · 预计 100–150 分钟 · 上一篇：第 5 课 · 正弦 PWM 流水灯

本课的胜利：用 50MHz 时钟分频得到人耳能听到的方波，让无源蜂鸣器发出一个音符； 再增加音符时长计数器，按表播放一段简单旋律。你会看到“频率”和“持续时间”是两个独立的时间尺度。

〇、开场复习

  1. 第 5 课中，pwm_cnt 的循环速度决定什么？phase 的更新速度决定什么？
  2. 若一个信号每 1us 翻转一次，它的完整周期是 1us 还是 2us？频率是多少？
  3. 为什么蜂鸣器输出需要寄存器保存，而不是在 testbench 里使用 # 延时生成？

本课的关键：计数器本身没有“频率”这个属性，计数到阈值后翻转输出，才形成周期信号。 输出每半个周期翻转一次，所以分频公式里有一个 2。

一、先确认蜂鸣器类型和引脚

征途 Pro 使用的是无源蜂鸣器。无源蜂鸣器不会自己产生固定音调，需要 FPGA 送入方波。 本课使用的引脚约束是：

端口引脚说明
clkPIN_E150MHz 板载时钟
rst_nPIN_M15低有效复位
keyPIN_M2KEY1，按下为 0，用来控制播放
beepPIN_J11无源蜂鸣器控制信号

LED 的低有效规则不能套到蜂鸣器上。蜂鸣器信号的极性以原理图和实测为准；本课 RTL 先生成普通 0/1 方波， 不对它额外取反。

二、一个音符如何从时钟中产生

以标准音符 A4 为例，目标频率约为 440Hz。50MHz 时钟周期为 20ns，方波每半周期翻转一次：

半周期计数值 = 50,000,000 / (2 × 440) - 1
              ≈ 56,817

每数到 56,817，beep 翻转一次
完整周期约为 113,636 个 clk
输出频率约为 440Hz

计数范围是 0..56,817，一共 56,818 个时钟。因此阈值写成“计算结果减一”，和前面流水灯的边界规则相同。

2.1 当前实现：状态寄存器加分频译码

当前工程采用你已经练习过的结构：melody_fsm 是音符状态寄存器， duration_cnt 到期时切换状态，组合 case (melody_fsm) 选择当前音符的分频值。 key=0 时播放，key=1 时停止并回到 A4。

// A-G 状态：A4 -> B4 -> C5 -> D5 -> E5 -> F5 -> G5 -> A4
reg [2:0] melody_fsm;

always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        duration_cnt <= 30'd0;
        melody_fsm   <= NOTE_A;
    end else if (key) begin
        duration_cnt <= 30'd0;
        melody_fsm   <= NOTE_A;
    end else if (duration_cnt == DURATION_CNT_MAX - 1) begin
        duration_cnt <= 30'd0;
        if (melody_fsm == NOTE_G)
            melody_fsm <= NOTE_A;
        else
            melody_fsm <= melody_fsm + 3'd1;
    end else begin
        duration_cnt <= duration_cnt + 30'd1;
    end
end

always @(*) begin
    case (melody_fsm)
        NOTE_A: tone_cnt_max = TONE_A;
        NOTE_B: tone_cnt_max = TONE_B;
        NOTE_C: tone_cnt_max = TONE_C;
        NOTE_D: tone_cnt_max = TONE_D;
        NOTE_E: tone_cnt_max = TONE_E;
        NOTE_F: tone_cnt_max = TONE_F;
        NOTE_G: tone_cnt_max = TONE_G;
        default: tone_cnt_max = TONE_A;
    endcase
end

这里的 melody_fsm 是当前状态，不需要另写 next_state； 它在时序块中按持续时间递增，在组合块中只负责译码。状态切换时同时清零 tone_cnt， 避免新音符从旧音符的半周期中间开始。

2.2 先用缩短参数验证

真实的音符持续时间很长，仿真时通过参数覆盖把每个音符压缩到少量时钟：

beep #(
    .DURATION_CNT_MAX(8)
) dut (...);

testbench 还可以临时 force dut.tone_cnt_max = 17'd2，快速观察方波翻转。 这种修改只用于仿真，不应写入综合用的 RTL。

场景检查
复位期间beep=0，计数器为 0
未使能输出保持 0，计数器不会累积
使能后输出每 4 个时钟翻转一次
关闭使能输出立即在下一个时钟回到 0，并重新开始计数

三、从单音扩展到旋律

字母音名和唱名的对应关系是 C=DO、D=RE、E=MI、 F=FA、G=SO、A=LA、B=SI。 因此本课按字母顺序播放 A→B→C→D→E→F→G，也就是 LA→SI→DO→RE→MI→FA→SO。

音调频率和音符持续时间属于两套计数器：

计数器作用典型数量
tone_cnt产生当前音符的高低电平翻转几十万以内
duration_cnt决定当前音符播放多久数百万到数千万

当前七个音符使用以下近似频率和半周期计数值：

note_div   = 当前音符的半周期分频值
note_ticks = 当前音符持续的时钟数

 A4: 56,818  // 440Hz
 B4: 50,618  // 494Hz
 C5: 47,777  // 523Hz
 D5: 42,565  // 587Hz
 E5: 37,921  // 659Hz
 F5: 35,792  // 698Hz
 G5: 31,887  // 784Hz

当 duration_cnt 到达当前音符的持续阈值时，melody_fsm 加一， tone_cnt 清零，重新按新的 tone_cnt_max 产生方波。

3.1 推荐的旋律控制结构

  1. 音符状态寄存器。使用 melody_fsm[2:0] 表示 A 到 G，复位后指向 A。
  2. 音符分频译码。用 case (melody_fsm) 输出 tone_cnt_max，不引入浮点。
  3. 音符时长计数。使用 DURATION_CNT_MAX 把每个音符的仿真时长压小。
  4. 音符切换。时长到达时状态循环，tone_cnt 和 beep 在边界清零。
  5. 按键控制。KEY1 按下时播放，松开时停止；输入按键沿用第 3 课的同步和消抖思想。

先后顺序：先完成单音，再加入音符索引，最后再接按键。一次同时改频率、时长、按键和消抖， 波形出了问题时很难定位。

四、命令行工程

新练习目录为 test/case/06-beep/：

06-beep/
├── src/beep.v
├── sim/tb_beep.sv
├── sp1_prj/beep.qpf
├── sp1_prj/beep.qsf
├── sp1_prj/beep.sdc
└── Makefile

Makefile 继续沿用第 5 课的入口：

make sim       # 编译并运行文本检查
make syntax    # 只编译 RTL 和 testbench，不运行仿真时间
make syntax-rtl # 只检查 RTL 源文件
make syntax-tb  # 只检查 testbench 源文件
make elab      # 装载顶层，检查端口/参数/模块连接，不运行时间
make wave      # 观察 tone_cnt、duration_cnt、melody_fsm、beep
make map       # Analysis & Synthesis
make fit       # Fitter
make sof       # 生成可下载文件
make timing    # 单独运行 TimeQuest
make program   # 只下载已有 SOF

当前工程只有一个 RTL 文件，ModelSim 的 vlog 需要同时编译它和 testbench：

$(MSBIN)/vlog -quiet \
    ../src/beep.v tb_beep.sv

vlog 是编译器：它会检查语法和编译期错误，但不会执行 initial、不会推进仿真时间。 vsim 才负责装载设计并运行仿真。make syntax 适合只检查代码能否编译； make elab 再多做一步顶层装载，能够发现模块不存在、端口不匹配、参数名写错等问题， 但同样不会播放波形或执行测试过程。

QSF 也必须登记每个源文件：

set_global_assignment -name TOP_LEVEL_ENTITY beep
set_global_assignment -name VERILOG_FILE ../src/beep.v
set_global_assignment -name SDC_FILE beep.sdc

set_location_assignment PIN_E1  -to clk
set_location_assignment PIN_M15 -to rst_n
set_location_assignment PIN_M2  -to key
set_location_assignment PIN_J11 -to beep

五、仿真验收

testbench 不需要“听声音”，它检查数字波形的周期和切换边界：

  1. 复位后 beep=0，所有计数器处于已知值。
  2. 播放状态下，统计若干个周期，确认相邻翻转间隔等于当前 tone_cnt_max 个时钟。
  3. 关闭使能后，确认输出停止且音调计数器清零。
  4. 旋律模式下，确认 melody_fsm 按 A-G 顺序循环，切换音符时 tone_cnt 重新开始。
  5. 使用 $fatal 让失败的检查返回非零状态，保证 make sim 能识别错误。

六、常见错误

  1. 声音比预期高一个八度：把半周期分频值误当成完整周期，或忘记方波每半周期翻转一次。
  2. 按键松开后仍有残音：禁用时没有清零 tone_cnt 和 beep。
  3. 音符切换时出现异常长脉冲：切换 tone_cnt_max 时没有清零 tone_cnt。
  4. 仿真等太久：没有通过参数覆盖把音调和音符时长压小。
  5. Quartus 找不到顶层：QSF 的顶层实体、RTL 文件名或相对路径写错。

七、通关标准

  1. 仿真能证明单音输出周期正确，启停行为确定。
  2. 上板按下 KEY1 后蜂鸣器发声，松开后停止。
  3. 旋律模式完成 A 到 G 的七个音符循环。
  4. 能解释：音调分频计数器和音符时长计数器为什么必须分开。
