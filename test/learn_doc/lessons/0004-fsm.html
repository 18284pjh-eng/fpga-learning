第 4 课 · 状态机 FSM：让电路记住自己在哪一步

对应教材：《FPGA Verilog 开发实战指南》第 14 章「状态机」 · 平台：野火征途 Pro · 预计 120–180 分钟 · 上一篇：第 3 课 · 按键消抖

本课的胜利：把“按下后等待、再判断松开”的过程画成状态图，写成一个同步有限状态机； 仿真验证短按与长按路径，并上板实现：短按让 LED 翻转一次，长按让 LED 快速闪烁。

〇、开场复习（合上资料答）

  1. 第 3 课的 key_flag 为什么只有一个时钟周期？下游怎样把它变成人眼可见的 LED 翻转？
  2. 消抖计数器数满后为什么停在最大值，而不是继续加到溢出？这对应哪一种“状态”？
  3. 按住 KEY1 不放，消抖模块应该只报告一次按下事件。要区分短按和长按，电路还需要记住什么？

答案核对：事件脉冲由时序逻辑捕获；计数器停在最大值是饱和状态；本课要记住“当前处于等待、按住还是完成”的阶段， 以及按住了多久。把有限的阶段和转移条件写清楚，就是 FSM。

一、先建立硬件思维：FSM 是带记忆的电路

组合逻辑只能回答“现在输入是什么”；寄存器能保存“上一个时钟沿之后的结果”。有限状态机把两者接在一起：

状态

由寄存器保存，例如 IDLE、PRESSED、LONG。状态只在时钟沿改变。

转移

由当前状态和输入决定下一状态，例如在 PRESSED 中，计时未到就继续等待，计时到就进入 LONG。

本课使用的状态图如下。圆圈是状态，箭头上的文字是“输入条件 / 输出事件”。输出事件仍然用一个时钟周期的脉冲表达。

当前状态条件下一状态事件
IDLEkey_in == 0PRESSED无
PRESSED松开IDLEshort_pulse
PRESSED计时达到长按阈值LONGlong_enable
LONG仍按住LONG周期性闪烁
LONG松开IDLE无

关键边界：状态机不是“软件线程”。所有状态寄存器仍由同一个 sys_clk 驱动； 状态转移只会在时钟上升沿发生。组合逻辑负责计算下一步，时序逻辑负责保存这一步。

二、推荐的三段式 FSM

把职责拆开，波形和综合结果都更容易检查。先记住结构，再填入本课的业务条件：

// 1. 状态寄存器：只保存 current_state
always @(posedge sys_clk or negedge sys_rst_n) begin
    if (!sys_rst_n)
        current_state <= IDLE;
    else
        current_state <= next_state;
end

// 2. 下一状态组合逻辑：只决定 next_state
always @(*) begin
    next_state = current_state;  // 默认自保持
    case (current_state)
        IDLE:    if (key_down) next_state = PRESSED;
        PRESSED: if (released)  next_state = IDLE;
                 else if (long_done) next_state = LONG;
        LONG:    if (released)  next_state = IDLE;
        default:              next_state = IDLE;
    endcase
end

// 3. 输出时序逻辑：脉冲默认清零，只在事件发生时拉高一拍
always @(posedge sys_clk or negedge sys_rst_n) begin
    if (!sys_rst_n)
        short_pulse <= 1'b0;
    else begin
        short_pulse <= 1'b0;
        if (current_state == PRESSED && released)
            short_pulse <= 1'b1;
    end
end

default 分支是硬件安全网：如果寄存器因上电、干扰或仿真初始化进入非法编码，电路会回到已知状态。 next_state = current_state 则避免组合逻辑遗漏条件而推导出不想要的锁存器。

三、实战 A：短按/长按控制器

练习场：test/case/04-key-fsm/，目录沿用前三课的 src/、sim/、sp1_prj/。

  1. 先画状态图和时序图。画出复位、稳定按下、长按阈值、松开四段；标出 short_pulse 的单拍位置，以及 long_enable 的持续有效区间。
  2. 写 src/key_fsm.v。本工程顶层模块名是 key_fsm，当前端口名为 clk、rst_n、key、led。建议先只完成短按路径，再加长按。QSF 中的端口名称必须和这里逐字一致。
  3. 加入参数。用 parameter LONG_CNT_MAX 控制长按时长。真实板上可按 50MHz 计算，仿真例化时改成 20'd99，不要修改 RTL 中的物理时钟假设。
  4. 连接输出。短按事件让 led 翻转一次；进入 LONG 后用一个小分频计数器让 LED 周期闪烁。LED 是寄存器，不要直接接一拍脉冲。
  5. 用文本写工程约束。创建 sp1_prj/key_fsm.qpf 和 key_fsm.qsf，把顶层、器件、Verilog 文件和四个引脚写进去。约束文件是可审查、可复现的工程源文件，不必依赖 Pin Planner。

四、命令行主线：一个 Makefile 串起仿真、编译和下载

沿用第 3 课的 Makefile 习惯，新增 sim/tb_key_fsm.sv，并把 Makefile 放在练习根目录。先定义变量：

MSBIN := /tool/altera/13.0sp1/modelsim_ase/bin
QBIN  := /tool/altera/13.0sp1/quartus/bin
ROOT  := $(CURDIR)
PRJ   := $(ROOT)/sp1_prj
PROJECT := $(PRJ)/key_fsm
REV   := key_fsm
TOP   := tb_key_fsm
SOF   := $(PRJ)/key_fsm.sof
Q64   := --64bit
QP    := --parallel=8

.PHONY: sim wave map fit asm sof timing quartus program clean distclean

quartus_sh --flow compile 会依次完成 Analysis & Synthesis、Fitter、Assembler 和时序分析，适合完整检查； 练习中用 Map、Fit、Assembler 拆开的目标生成 .sof，再用单独的 timing 目标运行时序分析：

sim:
	cd sim && $(MSBIN)/vlib work
	cd sim && $(MSBIN)/vlog -quiet ../src/key_fsm.v tb_key_fsm.sv
	cd sim && $(MSBIN)/vsim -c $(TOP) -do "vcd file key_fsm.vcd; vcd add -r sim:/$(TOP)/*; run -all; quit -f"

wave: sim
	gtkwave sim/key_fsm.vcd

map:
	$(QBIN)/quartus_map $(Q64) $(QP) $(PROJECT) -c $(REV)

fit: map
	$(QBIN)/quartus_fit $(Q64) $(QP) $(PROJECT) -c $(REV)

asm: fit
	$(QBIN)/quartus_asm $(Q64) $(PROJECT) -c $(REV)

sof: asm
	@test -s $(SOF)

timing: fit
	$(QBIN)/quartus_sta $(Q64) $(QP) $(PROJECT) -c $(REV)

quartus:
	$(QBIN)/quartus_sh $(Q64) --flow compile $(PROJECT)

program:
	@test -s $(SOF) || { echo "SOF not found; run 'make sof' first"; exit 1; }
	$(QBIN)/quartus_pgm -c USB-Blaster -m JTAG -o "p;$(SOF)"

clean:
	rm -rf sim/work sim/key_fsm.vcd sim/transcript $(PRJ)/db $(PRJ)/incremental_db $(PRJ)/output_files

distclean: clean
	rm -f $(SOF) $(PRJ)/*.rpt $(PRJ)/*.summary $(PRJ)/*.sof

常用入口是 make sim、make wave、make sof、make timing 和 make program。 make sof 只运行生成可下载文件所需的 Map、Fit 和 Assembler；make timing 单独运行 TimeQuest； make quartus 才运行完整流程。make program 只烧录已有的 .sof，不会因为烧录而重新编译。 下载前确认 jtagconfig 能看到 USB-Blaster。

4.1 从零创建 Quartus 工程描述文件

先分清两个文件各自负责什么：

文件作用你可以怎样理解
key_fsm.qpfQuartus Project File，指定工程修订版（revision）名称。工程入口/目录索引。
key_fsm.qsfQuartus Settings File，保存器件、顶层、源文件和引脚等设置。工程配置清单。

两个文件名的主干要一致，且本课把它们放在 sp1_prj/。从仓库根目录执行：

cd /home/pjh/project/fpga_learning
mkdir -p test/case/04-key-fsm/sp1_prj

mkdir -p 会创建目录；目录已存在也不会报错。接下来用文本编辑器创建文件。下面用 shell here-document 展示完整内容， 你可以照着在编辑器里输入；如果直接复制命令，结尾的 EOF 必须单独占一行。

第一步：创建 sp1_prj/key_fsm.qpf。这三项分别是 Quartus 文件格式版本、文件生成日期和工程 revision 名称：

cat > test/case/04-key-fsm/sp1_prj/key_fsm.qpf <<'EOF'
QUARTUS_VERSION = "13.0"
DATE = "09:00:00  SEPTEMBER 26, 2026"
PROJECT_REVISION = "key_fsm"
EOF

PROJECT_REVISION 必须与工程名相符。Quartus 会据此读取同目录下的 key_fsm.qsf，所以别把一个文件叫 key_fsm、另一个叫 fsm。

第二步：创建 sp1_prj/key_fsm.qsf。先照当前顶层模块和端口名填写：

cat > test/case/04-key-fsm/sp1_prj/key_fsm.qsf <<'EOF'
set_global_assignment -name FAMILY "Cyclone IV E"
set_global_assignment -name DEVICE EP4CE10F17C8
set_global_assignment -name TOP_LEVEL_ENTITY key_fsm
set_global_assignment -name VERILOG_FILE ../src/key_fsm.v

set_location_assignment PIN_E1  -to clk
set_location_assignment PIN_M15 -to rst_n
set_location_assignment PIN_M2  -to key
set_location_assignment PIN_L7  -to led
EOF

每行的意思：

QSF 设置作用
FAMILY芯片系列；征途 Pro 使用 Cyclone IV E。
DEVICE具体 FPGA 型号；板上是 EP4CE10F17C8。
TOP_LEVEL_ENTITYQuartus 从哪个 Verilog 模块开始搭建整张电路图；这里是 module key_fsm。
VERILOG_FILE加入要编译的 RTL 源码。相对路径从工程目录 sp1_prj/ 出发，../src/key_fsm.v 因此回到本课的 src/。
set_location_assignment把顶层端口接到芯片封装引脚。-to 后面必须是 RTL 顶层端口名，而不是你想起的别名。

本工程当前的对应关系是：板载 50MHz 时钟接 PIN_E1，低有效复位接 PIN_M15，KEY1 接 PIN_M2，低电平点亮的 LED 接 PIN_L7。 如果你把 Verilog 端口从 clk/rst_n/key/led 改名成 sys_clk/sys_rst_n/key_in/led_out，QSF 四个 -to 名称也要一起改；引脚编号保持不变。

4.2 添加最小时序约束（SDC）

QSF 负责告诉 Quartus“有哪些文件和引脚”，SDC 负责告诉 TimeQuest“这些信号应该以什么时间工作”。 没有 SDC 时，Quartus 仍然可以综合、布局布线并生成 .sof，但它不知道 clk 的真实频率， 时序报告和部分优化就没有可靠依据。本板的时钟是 50MHz，因此一个周期是：

1 / 50,000,000 Hz = 20 ns

在工程目录中创建 sp1_prj/key_fsm.sdc：

create_clock -name clk -period 20.000 [get_ports {clk}]
derive_clock_uncertainty

create_clock 将顶层端口 clk 定义为 20ns 周期；derive_clock_uncertainty 让 Quartus 根据器件和时钟生成默认不确定度。这里没有给 key 或 rst_n 随意添加输入延时：它们来自按键， 并且 key 先经过同步触发器；没有外部器件时序数据，就不应该编造一个输入延时数字。

然后在 key_fsm.qsf 中加入：

set_global_assignment -name SDC_FILE key_fsm.sdc

路径相对于 sp1_prj/，所以文件名直接写 key_fsm.sdc。用命令行验证：

cd test/case/04-key-fsm
make timing

日志中应看到类似 create_clock -period 20.000 -name clk，不应再看到“SDC file not found”或工具自动猜测 create_clock -period 1.000。时序约束不会让烧录动作变慢；它只在 Map/Fit/TimeQuest 阶段影响优化和检查。

第三步：自己检查文件和路径。

cat test/case/04-key-fsm/sp1_prj/key_fsm.qpf
cat test/case/04-key-fsm/sp1_prj/key_fsm.qsf
test -f test/case/04-key-fsm/src/key_fsm.v && echo "RTL path OK"

这一步不打开 Quartus GUI。QPF/QSF 都是普通文本，所以可以用 cat 查看、用 Git diff 审核；编译时 Quartus 会读取它们。

第四步：从命令行打开并编译这个工程。在本课根目录运行：

cd test/case/04-key-fsm
/tool/altera/13.0sp1/quartus/bin/quartus_sh --flow compile sp1_prj/key_fsm

Quartus 根据 sp1_prj/key_fsm.qpf 找到 revision，再读 key_fsm.qsf 中的设置。 make sof 完成分析综合、布局布线和 Assembler 后，.sof 位于 sp1_prj/key_fsm.sof； make timing 再单独运行 TimeQuest。当前 FSM RTL 仍是练习草稿，完成 RTL 后再期待编译通过；若失败，先看终端最早出现的 Error， 区分 Verilog 错误与 QSF 路径/端口名错误。

QSF 是实际编译使用的配置。Pin Planner 可以打开来核对分配结果，但你无需通过 GUI 才能创建或维护工程约束。

五、用 Makefile 验证每条路径

这一节的目标不是“把波形跑出来”，而是让 testbench 对每一条状态转移提出一个可检查的问题： 复位后在哪里？稳定按下后是否进入 PRESSED？短按是否只翻转一次？长按是否等到计数完成才进入 LONG？

5.1 先把真实时间缩小

RTL 默认参数面向开发板：50MHz 时钟下，消抖约 20ms，长按约 1s，LED 分频也需要较长时间。 如果 testbench 直接使用这些值，每个场景要等待数千万个时钟。仿真时通过例化参数覆盖把它们缩小， 但时钟仍保持 50MHz 的时间关系：

key_fsm #(
    .CNT_MAX(3),
    .BLINK_DIV_MAX(4),
    .LONG_CNT_MAX(8)
) dut (
    .clk  (clk),
    .rst_n(rst_n),
    .key  (key),
    .led  (led)
);

这三个数只服务于仿真速度。不要把 testbench 的小参数写回 RTL 默认值，否则上板后的时间尺度会被改变。

5.2 先写时钟、复位和按键动作

按键是低有效：key=1 表示松开，key=0 表示按下。时钟每 10ns 一个周期，复位保持几个周期后再释放。 建议先创建 sim/tb_key_fsm.sv，只写下面的骨架，然后逐步加入检查：

`timescale 1ns/1ps

module tb_key_fsm;
    reg clk = 1'b0;
    reg rst_n = 1'b0;
    reg key = 1'b1;
    wire led;
    integer errors = 0;

    localparam integer DEBOUNCE_MAX = 3;
    localparam integer BLINK_MAX = 4;
    localparam integer LONG_MAX = 8;

    always #5 clk = ~clk;

    key_fsm #(
        .CNT_MAX(DEBOUNCE_MAX),
        .BLINK_DIV_MAX(BLINK_MAX),
        .LONG_CNT_MAX(LONG_MAX)
    ) dut (
        .clk(clk), .rst_n(rst_n), .key(key), .led(led)
    );

    task automatic tick(input integer n);
        repeat (n) @(posedge clk);
    endtask

    task automatic check(input integer condition, input [8*80-1:0] message);
        if (condition)
            $display("PASS: %0s", message);
        else begin
            $display("FAIL: %0s", message);
            errors = errors + 1;
        end
    endtask

    initial begin
        // 场景将在这里依次加入
        tick(4);
        rst_n = 1'b1;
        tick(4);

        if (errors == 0) $display("TEST PASS");
        else $display("TEST FAIL: %0d error(s)", errors);
        $finish;
    end
endmodule

tick 把“等待几个时钟沿”封装起来，避免在每个场景中散落很多 # 延时。 检查状态时使用 @(posedge clk); #1 或 tick(1); #1，给非阻塞赋值留出一个 delta cycle， 再读取波形和内部寄存器。

5.3 按场景逐个验证

场景 A：复位。复位期间检查 dut.cur_state == 2'd0、dut.short_pulse == 0、 dut.long_enable == 0，释放复位后再等待同步器稳定。这里用数字是因为当前 RTL 用 localparam 声明状态编码， testbench 不能直接访问模块内部的局部参数名。

场景 B：短按。先让 key=0，保持足够长时间让双触发器和消抖计数完成； 但在 LONG_MAX 到达前恢复 key=1。检查顺序应是：

  1. 稳定按下后，dut.cur_state 进入 PRESSED（编码 2'd1）。
  2. 释放后，dut.short_pulse 只为 1 个时钟周期。
  3. dut.long_enable 从未出现，最终状态回到 IDLE。
  4. led 相比按下前只翻转一次。

“只为一拍”不要只看它最终为 0；可以在每个时钟沿累加一个 short_count，仿真结束时检查它是否等于 1。

场景 C：长按。按下后保持超过 LONG_MAX，检查 long_press_cnt 逐渐增加， 计数完成前仍停留在 PRESSED；达到阈值后才进入 LONG（编码 2'd2）。 进入 LONG 后，当前 RTL 的 long_enable 是持续使能，不是单拍事件，所以不要把它当作脉冲计数。 此时重点检查 blink_div_cnt 周期性归零、led 周期性翻转；释放后状态回到 IDLE， 并确认下一次长按从清零后的计数重新开始。

场景 D：非法状态恢复。这是检查 default 分支的专门场景，不代表真实硬件中可以随意写状态寄存器。 在 testbench 中可以临时使用层次引用：

force dut.cur_state = 2'b11;
@(posedge clk);
#1 check(dut.next_state == 2'd0, "illegal state returns to IDLE");
release dut.cur_state;

force/release 只应出现在仿真代码中；这里的 release 是 Verilog 的仿真语句， 不能拿来命名 RTL 信号。

5.4 用 Makefile 运行和看波形

完成 testbench 后，在练习根目录运行：

cd test/case/04-key-fsm
make sim

终端必须看到每个场景的 PASS，最后看到 TEST PASS。testbench 在有错误时调用 $fatal， 因此 make sim 也会返回失败状态。出现失败时，先看第一个失败的检查，不要先从最后的波形猜原因。确认文本检查通过后再运行：

make wave

GTKWave 中加入或观察这些信号：

  • 输入：clk、rst_n、key；
  • 状态：dut.cur_state、dut.next_state；
  • 计数：dut.debounce_cnt、dut.long_press_cnt、dut.blink_div_cnt；
  • 输出：dut.short_pulse、dut.long_enable、led。

先 Zoom Fit，再逐个场景放大。短按事件应宽一个时钟周期，即 10ns；不要把按键保持时间误认为事件脉冲宽度。 波形的作用是解释“为什么通过或失败”，$display 负责输出检查结果，$fatal 负责让 Makefile 识别失败。

七、检索练习

1. 三段式 FSM 中，状态寄存器的职责是什么？

状态寄存器是记忆元件，只在时钟沿更新；下一状态和输出的计算由另外的组合或时序逻辑完成。

2. 为什么事件脉冲通常在输出时序块开头默认清零？

每拍先清零，再在满足条件的那一拍置 1，脉冲自然只有一拍。异步输入同步化是另一个问题，需要双触发器等结构。

3. 在组合状态转移块中漏写某个分支，最可能出现什么问题？

组合逻辑必须对所有输入给出结果。默认自保持和 default 分支能减少遗漏，也让非法状态有恢复路径。

八、通关标准与下一课

  1. 仿真中短按、长按、释放三条路径都通过，事件脉冲没有多拍或漏拍。
  2. 上板后短按只翻转一次；长按进入可见闪烁；松开后回到空闲。
  3. 能解释：状态寄存器保存什么、转移条件在哪里、为什么输出脉冲必须被寄存器捕获。

完成后下一步是流水灯：把 FSM 的状态从“按键阶段”换成“LED 序列阶段”，练习状态编码、组合逻辑和多路输出。
